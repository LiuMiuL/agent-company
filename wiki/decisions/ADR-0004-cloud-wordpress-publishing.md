# ADR-0004 — 클라우드 워드프레스 발행은 로컬 편집국과 분리한다

- **상태**: 채택됨 (클라우드 경로 한정)
- **날짜**: 2026-11-20

## 맥락

지금까지 글은 로컬 편집국(`blog-writer`)이 `content/posts/*.md` 로 쓰고, 사람이 어드민에서
`published` 로 바꿔 발행했습니다. 그런데 실제 운영 사이트는 워드프레스(`manyinfo.net`)이고,
PC 가 꺼져 있어도 GitHub Actions 에서 글을 만들어 **임시저장**까지 해 두고 싶다는 요구가 생겼습니다.

이 요구는 코어 하드 룰 두 개와 부딪힙니다.

1. **이미지 생성 경로는 하나다(Codex imagegen).** 클라우드 러너에는 Codex CLI 가 없습니다.
2. **출고 버튼은 사람이 누른다.** 클라우드에서 자동으로 발행하면 이 규칙이 흔들립니다.

## 결정

**클라우드 워드프레스 발행을 에이전트 로스터 밖의 별도 경로로 둡니다.**
`scripts/wp-publish.mjs` 와 `.github/workflows/wp-publish.yml` 이 그 경로이며, 에이전트가
아니라 **사람이 실행하는 자동화**입니다.

1. **저장소 콘텐츠와 분리한다.** 이 경로는 `content/posts/` 를 읽지도 쓰지도 않습니다.
   결과는 워드프레스와 실행 아티팩트(`out/wp-publish/`)에만 남습니다.
2. **하드 룰 1은 로컬 파이프라인에 적용된다.** 클라우드 경로의 대문 이미지는 OpenAI Images
   (`gpt-image-1`) 한 가지로만 만들고, 그 사실과 모델·프롬프트를 실행 결과 JSON 에 기록합니다.
   클라우드 경로 안에서도 이미지 모델은 하나입니다. 로컬 `blog-writer`·`image-maker` 의
   규칙(Codex 전용)은 그대로입니다.
3. **하드 룰 2는 입력으로 지킨다.** 기본값은 `draft`(임시저장)입니다. `publish` 는 사람이
   `workflow_dispatch` 화면에서 `status=publish` 를 **명시적으로 고를 때만** 일어납니다.
   에이전트가 스스로 이 워크플로우를 부르지 않습니다.
4. **개인정보·사실 확인.** 프롬프트가 작성자의 이름·주소·직장·학교·계정·구매 이력을 금지하고,
   검색 도구가 없으므로 확인되지 않은 가격·날짜·통계를 단정하지 않습니다. 확인이 필요한 항목은
   `fact_check_notes` 로 돌려주어 Summary 에 표시합니다.

## 강제 수단

문서로만 두지 않고 실행 경로에 박아 둡니다.

| 층 | 수단 |
| --- | --- |
| 기본값 | `POST_STATUS` 기본 `draft`, 워크플로우 select 기본 `draft` |
| 입력 | `publish` 는 choice 항목 — 사람이 골라야만 전달됨 |
| 검증 | `DRY_RUN=true` 는 워드프레스에 쓰지 않고 결과 JSON 만 남김 |
| 비밀 | 키·비밀번호는 환경변수로만. 저장소·로그·결과 파일에 기록하지 않음 |
| 본문 | `sanitizeHtml()` 이 `script`·`style`·`iframe`·`img`·`on*`·`javascript:` 를 제거 |
| 정리 | 프로필에서 응용 프로그램 비밀번호를 폐기하면 즉시 끊김 |

## 트레이드오프

- **버전 관리 밖이다.** 클라우드에서 만든 글은 저장소에 커밋되지 않습니다(하드 룰 3과 긴장).
  초안을 오래 보관하려면 아티팩트(14일)에서 꺼내 `content/posts/` 로 옮기는 것은 사람의 판단입니다.
- **이미지 스타일이 로컬과 다를 수 있다.** 그래서 대문 이미지 한 장으로 한정했습니다.
- **클라우드 LLM 은 검색하지 못한다.** 최신 정보 글은 초안 검수가 더 필요합니다. 이 사실을
  Summary 에 항상 표시합니다.
